0. 文档使用说明与开发结论
本文档用于直接交给 Trae 进行项目开发。除标记为“后续版本/实验性”的内容外，均按第一版产品需求理解。开发过程中若底层第三方组件能力与本文冲突，以“用户体验不变、传输层可替换、控制面与数据面解耦”为最高原则。
0.1 第一版必须遵守的 10 条原则
普通用户不能被要求理解 N2N、STUN、ICE、Supernode、Cloudflare Tunnel、WARP、CIDR、端口映射等概念。
管理员的日常创建流程必须保持：输入节点 IP → 选择是否设置密码 → 点击“创建并连接”。
连接成功后必须自动生成可分享的 .meshjoin 配置，同时支持复制邀请链接；二维码可放入第二阶段。
DirectLink P2P 必须独立于 N2N：即使 N2N edge 进程崩溃，DirectLink 仍可继续建立和维护 P2P。
N2N 是可替换 Transport Provider，而不是整个产品的唯一网络核心。
Cloudflare Tunnel 第一版主要承担 Controller/API/WebSocket Relay 的公网入口；不要把免费 Tunnel 错当成任意公网 UDP 端口映射。
已建立的数据路径不能因为 Controller 暂时离线而立即中断；客户端需要缓存必要的 Peer/路径状态。
所有敏感密钥必须安全存储，分享配置不得包含 Cloudflare API Token、Tunnel Token、管理员 Token 或永久网络私钥。
路径切换必须具备熔断、半开探测、防抖、自动回切机制，避免线路频繁抖动。
第一版优先把 Windows 端做稳定，再为 macOS/Linux 预留接口，不要求第一版同时跨平台。

1. 项目定位与产品目标
本项目是一套面向 Windows 桌面环境的智能虚拟局域网/组网系统。系统由“管理员桌面控制台”和“普通客户端”组成，并配套 Controller、Node Agent、DirectLink P2P 引擎、N2N edge/supernode 以及 Cloudflare 接入组件。
核心目标不是制作一个 N2N GUI，而是建立一层可自主管理、可自动调度、可熔断、可替换底层传输的 Overlay 网络平台。
1.1 产品目标
P2P 直连优先：尽量让两台设备直接 UDP 通信，降低延迟并减少中继流量。
N2N 兜底：P2P 失败时可使用 N2N Supernode 进行中继；支持多个 Supernode 与健康调度。
N2N 故障时仍可 P2P：DirectLink 与 N2N 相互独立，N2N 进程故障不得阻塞 P2P。
Cloudflare 免公网入口：Controller 与 WebSocket Relay 可部署在无公网 IP 的机器上，通过 Tunnel 提供稳定域名入口。
极简使用：管理员输入 IP 即可创建连接；朋友导入配置即可加入。
可选密码：创建者可启用或禁用网络访问密码。
自动调度：根据 RTT、丢包、抖动、节点负载、故障次数等自动选择最优路径。
实时可观测：管理员可以查看在线设备、路径、拓扑、流量、节点状态与告警。
1.2 非目标（第一版不做）
不做完整企业 IAM/SSO 平台。
不做手机端。
不做复杂 SD-WAN 全功能路由器能力。
不要求第一版实现内核级 WireGuard 替代。
不承诺 Cloudflare Tunnel 免费版提供任意公网 UDP 入口。
不以“修改 Windows 路由表绕过所有网络限制”为卖点。

2.1 典型场景
1.  用户在家中/办公室的一台 Windows 主机安装 Node Agent。
2.  管理员控制台输入该主机 IP，例如 192.168.1.50。
3.  管理员选择“无密码”或“使用自定义密码”，点击“创建并连接”。
4.  系统自动完成 Agent 检测、网络初始化、P2P/N2N/Cloudflare 状态检测、虚拟网段创建。
5.  成功后自动生成“我的网络.meshjoin”。
6.  管理员把配置文件发给朋友。
7.  朋友双击或在普通客户端中导入，输入密码（如启用），点击连接。
8.  系统优先 DirectLink P2P，失败后选择 N2N 路径，最终可用 Cloudflare WebSocket Relay 灾备。

6. DirectLink 独立 P2P 引擎
DirectLink 是本项目必须自研或基于成熟 ICE 库封装的独立 P2P 数据通道。它不能依赖 N2N supernode、N2N edge 或 N2N management API 才能工作。
6.1 功能
STUN 获取公网映射地址。
收集 host/server-reflexive 等候选地址。
通过 Controller 交换 Candidate。
UDP Hole Punch / ICE Connectivity Check。
Keepalive 保持 NAT Binding。
会话密钥协商与报文加密。
路径 RTT/丢包/抖动测量。
MTU 探测与分片策略。
断线重连与 endpoint 更新。
6.2 DirectLink 状态机
IDLE → GATHERING → CHECKING → READY → ACTIVE                       ↓失败        ↓异常                     FAILED ← DEGRADEDACTIVE 出现持续异常：进入 DEGRADED，Path Manager 可切换到 N2N/Relay；后台继续 CHECKING，恢复后满足回切条件再切回。
6.3 热备要求
即使当前业务正在走 N2N Relay，也应保持 DirectLink 的 Candidate 信息和低频 Keepalive，以便 N2N 出现故障时快速切回 P2P，而不是故障后才从零开始 STUN/打洞。
7. N2N 引擎与 Supernode 节点池
N2N 官方机制会优先尝试 edge 之间 UDP P2P，无法直连时由 supernode 中继，并支持一个 edge 配置多个 supernode。系统应利用这一能力，但不能把 N2N 作为唯一数据面。

7.3 N2N 管理采集
N2N edge 和 supernode 均提供 UDP 管理接口，默认 edge 管理端口 5644、supernode 5645，并支持机器可读 JSON 查询。生产环境中管理接口仅绑定 localhost，由本机 SN-Agent/MeshAgent 读取后上报 Controller，禁止直接开放到公网。
8. Cloudflare 方案与部署模式
8.1 模式 A：第一版推荐 - Tunnel 控制面 + WebSocket 灾备
朋友 Client ──HTTPS/WSS──► Cloudflare Edge                            │                       Cloudflare Tunnel                            │                  ┌─────────▼─────────┐                  │ Controller / Relay│                  │ 127.0.0.1:8080    │                  └───────────────────┘
优点：朋友不需要 Cloudflare 账号、不需要安装 WARP；Controller 所在机器不需要公网 IP 或开放 80/443。WebSocket Relay 可作为所有 UDP/N2N 均不可用时的最终灾备。
Cloudflare WebSocket Relay 设计
客户端通过 wss://relay.example.com/v1/relay 建立长期连接。
应用层帧包含 network_id、source_peer、target_peer、sequence、ciphertext。
Relay 不持有端到端业务明文密钥，仅转发密文帧。
Relay 只作为最后一级路径，避免长期占用带宽。
必须限速、限连接数、限单包大小，并记录每设备流量。
8.2 模式 B：公网 UDP N2N Supernode（生产推荐）
对于 N2N Supernode，最可靠做法仍是拥有公网 UDP 的 VPS/主机。Controller 可以通过 Cloudflare Tunnel 隐藏，但 N2N supernode 端口直接对外提供 UDP。Supernode 可以多节点部署，并由 Scheduler 返回 Primary + Backup 列表。
8.3 模式 C：Cloudflare Private Network + WARP（可选实验）
Cloudflare 私网路由能够让加入 Zero Trust 组织的终端访问 Tunnel 后的非 HTTP 私网资源。该模式要求朋友设备安装 Cloudflare One Client/WARP 并完成组织注册。因此不作为普通用户默认流程。
实验性功能：如果要尝试“N2N Supernode 放在 Cloudflare 私网后”，必须单独做 PoC 验证 UDP 会话、源地址/源端口保持、N2N 注册与中继行为，测试通过后才允许进入正式功能。不要把它写成 MVP 必然可行的依赖。

8.4 Cloudflare 首次初始化
1.  管理员进入“设置 → Cloudflare”。
2.  填写/授权最小权限 API Token，选择 Account/Zone。
3.  系统创建或绑定 Tunnel，生成 Controller Hostname 与 Relay Hostname。
4.  Controller 机器安装 cloudflared，并以系统服务运行。
5.  以后创建网络不再要求管理员输入 Cloudflare 参数。
9. 路径调度、熔断与故障转移
9.1 推荐路径优先级
1. DirectLink P2P      ↓不可用2. N2N P2P      ↓不可用3. Primary N2N Supernode Relay      ↓不可用4. Backup N2N Supernode Relay      ↓不可用5. Cloudflare WebSocket Relay
Path Manager 可并行探测多个候选路径，但任何时刻每个 Peer 只选择一个 Active Path；迁移时需考虑现有会话与乱序。

9.5 防抖与自动回切
新路径至少连续健康 10 秒后才允许抢占。
新路径质量需比当前路径高至少 20%，或当前路径已经 DEGRADED。
同一 Peer 两次路径切换最小间隔建议 15 秒。
切回 P2P 前至少完成 3 次连续 connectivity check。
路径切换事件必须写入事件中心，记录 from/to/reason/score。

10.2 .meshjoin 设计原则
文件尽可能小，只保存“如何找到 Controller + 如何证明这是一份有效邀请”。
不得保存 Cloudflare API Token、Tunnel Token、管理员 Token。
不得保存可长期复用的网络主密钥。
必须带 Controller 公钥指纹/签名，避免恶意配置劫持到伪造服务器。
Invite Token 可设置一次性/多次、有效期、是否需要审批。
10.3 推荐结构
{  "format": "meshjoin",  "version": 1,  "network": { "id": "net_8f21ac", "name": "我的网络-7A31" },  "controller": {    "url": "https://control.example.com",    "fingerprint": "SHA256:..."  },  "invite": {    "id": "inv_xxx",    "token": "one-time-or-limited-token",    "expires_at": "2026-08-30T22:00:00+08:00"  },  "flags": { "password_required": true },  "signature": "..."}
10.4 双击导入
Windows 安装器注册 .meshjoin 文件关联。双击配置直接打开普通 Client 的“加入网络”确认页。第二阶段可注册自定义 URI：meshlink://join/<token>。
11. 自定义密码与安全认证
11.1 用户体验
创建网络时提供“无密码 / 使用自定义密码”二选一。启用密码后，朋友导入 .meshjoin 时必须输入正确密码才允许完成设备注册。
11.2 密码存储
Controller 只保存 Argon2id 密码验证值（salt + hash + 参数），不保存明文。
客户端输入密码后通过 TLS 发送到 Controller 的认证接口；更严格实现可使用 PAKE，但第一版可先用 TLS + 速率限制。
分享配置只保存 password_required=true，不保存密码。
管理员可修改密码或取消密码。
11.3 修改密码策略
选项
行为
仅新设备使用新密码
已有已授权设备 Token/证书继续有效，新加入必须新密码。
要求全部设备重新认证
吊销现有网络成员会话/设备授权，下一次连接必须重新输入密码。

11.4 防暴力破解
单 IP/单设备 5 次失败后指数退避。
服务端记录失败事件与来源摘要。
邀请 Token 与密码验证双重校验。
管理员可撤销邀请、踢出设备、吊销设备证书。

18.2 N2N Process Supervisor
检测 edge.exe 崩溃：T+0    N2N Provider Circuit → OPENT+0    Path Manager 优先切 DirectLink/其他 RelayT+2s   后台尝试启动 edge.exe成功   → HALF_OPEN，执行健康探测连续探测成功 → CLOSED失败   → 指数退避重试，但不得阻塞其他 Transport
18.3 权限
安装器以管理员权限安装 Windows Service、虚拟网卡驱动/适配器及必要防火墙规则。日常 UI 不要求管理员权限；高权限操作通过受控 IPC 请求 Service 执行。

23. 第一版验收标准
管理员能安装软件，在目标 Agent 已安装的前提下，只输入 IP、选择密码模式、点击一次即可创建网络。
创建成功自动生成 .meshjoin；朋友导入后可以加入。
启用密码时，错误密码不能加入；关闭密码时不弹密码输入。
两台可打洞设备优先显示 Direct P2P。
Direct P2P 不可用时自动使用 N2N P2P/Supernode Relay。
强杀 n2n edge.exe 后，如果 DirectLink 已可用，应能自动切到/保持 DirectLink，不要求用户操作。
Primary Supernode 掉线能切 Backup；恢复后按防抖规则回切。
Controller 经 Cloudflare Tunnel 在无公网 IP 场景可被朋友客户端访问。
UDP/N2N 均不可用时，Cloudflare WSS Relay 能作为最后灾备进行基本 IP 数据传输。
管理员能看到设备在线状态、当前路径、RTT、丢包、流量、Supernode 健康与路径切换事件。
Controller 临时重启不应主动断开已有 DirectLink/N2N 数据通道。
分享文件不包含 Cloudflare Token、管理员凭证、明文密码。

结语
本项目第一版的核心不是堆叠功能，而是把复杂网络能力封装成简单可靠的用户体验：创建者只需要“IP + 可选密码 + 连接”，成员只需要“导入 + 密码（如有）+ 连接”。底层通过 DirectLink、N2N、Supernode Pool、Cloudflare Relay 与熔断器共同保证连接成功率和故障恢复能力。开发时优先保证模块解耦、可观测、可回退，再逐步增加高级策略和 Cloudflare 私网实验能力。
